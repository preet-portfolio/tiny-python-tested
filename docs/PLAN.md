# Tiny Python Projects, tested live — plan

**Thesis: the tests are the spec.** A visitor sees a red test, edits real Python, and watches it
go green in the browser. Each chapter then adds *real-world scenarios*: cases the author's spec
doesn't cover, where the visitor decides whether the spec or the world is right.

## Sources and licensing

- Not used: the book's prose and the repo's `solution*.py` files. Solutions in
  `python/chapters/` are written from the tests.

## Architecture
```
python/
  upstream/<ch>/test.py      author's tests, untouched (MIT)
  chapters/<ch>/<prog>.py    my solution (argparse CLI)
  chapters/<ch>/test_scenarios.py   real-world cases (mine)
  chapters/<ch>/test_props.py       Hypothesis properties (seeded programs)
  tptl/shim.py               runs "./prog.py args < file" in-process: argv, stdin,
                             stdout+stderr, exit code. Replaces subprocess in Pyodide.
  tptl/mutate.py             AST mutation operators + kill matrix (runs in browser and CI)
  tptl/parity.py             runs the author's tests twice — real subprocess vs shim — and
                             fails if any outcome differs
web/                         Next.js (static export) on Vercel
  public/pyodide-bundle/     generated: chapter files + tests + tptl as JSON
  public/metrics/            generated by CI: coverage, mutmut score, parity, seed outputs
  worker: Pyodide 314.0.7 (CPython 3.14.2, pytest 9.0.2) in a Web Worker
```
CI (GitHub Actions, Python 3.14 to match Pyodide): ruff, mypy, pytest (native subprocess),
parity (subprocess vs shim), seed parity (native vs Pyodide-in-Node), coverage, mutmut →
JSON → committed to `web/public/metrics/` by the workflow. The site never shows a hand-typed
number.

## Per-chapter page
1. **Spec** — the author's tests, red. Editor with a starter (signature only, no logic).
2. **Run** — terminal: argv input, stdout, stderr, exit code.
3. **Break the tests** — toggle/edit a test, see what it was guarding.
4. **Mutate my code** — mutants of *your* code × tests: which test killed which mutant;
   survivors are the gaps in the spec.
5. **Real world** — scenario tests beyond the spec (e.g. "an hour", "a unicorn").

- Seeded programs: same seed → byte-identical output in CPython 3.14 and Pyodide (Node).
- axe + Lighthouse on the deployed URL, phone and desktop.
- 2–3 subagent testers, each given a persona and a task (see `docs/TESTER_BRIEF.md`).
- Portfolio: `src/data/work.json` "projects" entry; `npm run build` and `check:links` pass.
